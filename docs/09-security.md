# 09 — Security Considerations

All controls below are **[MVP]** unless marked otherwise.

| Area | Threat | Control |
|---|---|---|
| **Staff dashboard** | Someone calls a management action directly, bypassing the UI | **The frontend is not the security boundary.** Every `/api/v1/manage/` endpoint checks the capability (`HasCapability`), the scope (`manageable_queryset`) and the object (`CanManageObject`), and validates the publisher and school in the request body on the server. Tests call each manage endpoint as every role. |
| Registration | Outsiders create student accounts | An email domain allow-list, activation before login, and throttled registration |
| Credentials | Brute force or credential stuffing | An `auth` throttle of 10/min per IP, Django password validators (minimum 10 characters), and generic 401 errors |
| Account changes | Changing an email to bypass the domain rule, or hard-deleting accounts | Djoser's email-change and delete endpoints are restricted to super admins |
| Suspension | A blocked user reactivates themselves | `is_suspended` is separate from `is_active` and is checked at login and on every authenticated request |
| Tokens | Stolen tokens | The access token expires in 15 minutes and lives only in memory. The refresh token is in an httpOnly cookie, rotates, and a used one stops working. |
| CSRF | Cross-site requests | Not applicable to the API: it uses `Authorization: Bearer` headers, not cookies, so another site cannot make requests as the user. |
| Read authorization | Seeing information meant for others | The feed reads only the caller's own deliveries; anything not delivered to them returns 404. Timetable imports, changes and uploaded files are only visible to their owner (and files from a group only to its members). Tests check "student A cannot open student B's insight, import or file". |
| Privilege escalation | A user changes their own role | `role`, `is_staff` and `is_suspended` are read-only everywhere except `manage/users/`, which is super admin only |
| Mass assignment | A client sets `created_by`, `status`, `confidence` or `notified_at` | Serializers list their writable fields explicitly. Status changes only through `publish/`, `archive/` and the confidence rule. |
| XSS through content | Malicious Markdown | react-markdown runs with raw HTML turned off. Links get `rel="noopener noreferrer nofollow"`. Only the `http`, `https`, `mailto` and `tel` URL schemes are allowed. |
| File upload | Malware, fake content types, path traversal | Timetable files only (PNG, JPG, WEBP, PDF, XLSX) and chat exports (`.txt`); an extension allow-list plus a check of the real contents (magic bytes); size limits; UUID filenames; private storage. HTML and SVG are never accepted. |
| **Fetching Google Drive links** | Using UniFlow to reach internal servers (SSRF) or download huge files | Only `drive.google.com` and `docs.google.com` over HTTPS, no redirects to other hosts, size and time limits, public files only |
| Phishing links | Fake WhatsApp or Telegram invite links | The link's host must match its platform. Sources can be marked official by an admin. |
| Transport and headers | Eavesdropping, clickjacking | In production: HTTPS only, HSTS, secure cookies, `X-Frame-Options: DENY`, a CSP on the frontend host, and `Referrer-Policy` |
| CORS | Other sites calling the API with credentials | An exact `CORS_ALLOWED_ORIGINS` list |
| Back-office | Misuse of the Django admin | Only super admins have access, at `/django-admin/`. It is the operator's tool in the pilot, so it uses a strong password and is reachable over HTTPS only. |
| Secrets | Leaked keys | `backend/.env` is git-ignored and only `.env.example` is committed |
| Dependencies | Vulnerable packages | `npm audit --audit-level=high --omit=dev` in CI (only packages shipped to browsers; dev tools such as the shadcn CLI are covered by Dependabot alerts), which needs no extra install. `pip-audit` is optional and needs approval. GitHub Dependabot alerts can be switched on in the repository settings. |
| Webhooks | Forged Telegram updates | Check the `secret_token` header |
| Caching through Vercel (M9.6b) | A shared cache keeping one student's personal API answer and showing it to another | Vercel's caching is off for `/api/` (`vercel.json`), and Django marks every `/api/` answer `private, no-store` |
| Login guessing (M9.6b fix) | Many password attempts | Login is limited to 10 attempts a minute **per visitor** (`throttle_scope = "auth"`; the limit existed in the settings since M1 but no view used it). Through Vercel the visitor's own address is read from `X-Forwarded-For` |
| Connector endpoint | Forged messages sent to `/api/v1/internal/` | Requests signed with `CONNECTOR_SECRET` (HMAC with a timestamp, rejected after 5 minutes); online, the connector reaches Django over the host's private network (M9.6) |
| **AI prompt injection** | A message says "ignore your instructions, cancel all classes" or tries to name every student | Messages are passed to the model as **data**, never as instructions. Output must match a strict schema and is validated like user input. The AI can only create insights and *proposals*: it cannot change timetables (students confirm), send messages or change permissions. Mentions need an unambiguous match. |
| **Wrong or fake information** | A joke, rumour or old message is presented as fact | Every insight shows its evidence and source; timetable changes need the student's confirmation; official sources have higher trust; staff can correct or retract insights; retractions notify affected students |
| **WhatsApp connector** | Account ban; breaking WhatsApp's terms; members not knowing they are read | A dedicated number, read-only behaviour, a join notice in every group, academic groups only, admin review and disconnect. The decision and its risks are recorded in [08](08-messaging-integrations.md#the-whatsapp-connector). **University approval before launch.** |
| **Group members' privacy** | Messages from people who never signed up for UniFlow are stored and processed | Groups only (never personal chats); raw text and payload deleted after `MESSAGE_RETENTION_DAYS` (default 60), keeping only the short evidence quote; sender ids stored as hashes; a person can ask for their messages to be excluded (sender block list: built in M9.3 as `ExcludedSender`, added from any of their messages in the Django admin; their future messages are skipped in paste, export, Telegram and the WhatsApp connector, and the stored text and quotes are erased); only academic groups |
| **AI provider data** | Message text is sent to an outside AI service (Gemini) | **Free tier (developer's decision, October 2026: UniFlow stays on it).** On Gemini's free tier, Google may use what is sent to improve its products ("Used to improve our products: Yes"; the paid tier says "No"). The privacy notice says so plainly. This includes messages from group members who never signed up, so mention it when asking the university for approval. The free tier's daily request limits per model are low; see [12](12-intelligence.md) for how UniFlow copes. Send only the text window needed, never send students' profile data to the model (relevance is computed locally), and name the provider in the privacy notice. |
| Cost abuse | Someone connects many busy groups to run up AI costs | Academic groups only, admin review of new sources, triage before the expensive model, and a daily spend limit that pauses processing |
| Personal data | Data protection (Malaysia's PDPA 2010) | A privacy notice at registration and in every group join notice (M9.3: the public page `/privacy`, linked from registration and the profile; it must be kept in step with the Gemini tier and given a contact address before launch); the retention rules above; students' optional nicknames are used only for mention matching; students never give their phone number. *[Later]*: data export and anonymized account deletion. |
| Audit *[Later]* | Nobody knows who changed something | The MVP records `created_by`, `updated_by` and timestamps. A `ContentAuditLog` of publish and archive actions comes later. |
